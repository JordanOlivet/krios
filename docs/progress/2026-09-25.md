# Progress — 2026-09-25 (KOIOS core + network engine)

The last MVP piece: the K.O.I.O.S. core is in — multiblock, data XP with the
diversity window, classic levels, and the three upgrade modules wired into the
crusher.

## Design settled (Q&A, recorded in ../mods/01-industry-design.md)

Full 3×3×3 shell (26 Neural Casings) with the core fully encased at the center
— revised mid-session from a hollow-frame first cut. Once formed the structure
acts as **one entity**: all casings flip to a seamless texture (reads as one
big block) and any casing right-click opens the core UI. One face displays the
AI's living head (BER: eye tracking, blinks, boot static, learning pulse,
level-up flash), aimed at the builder by default and re-aimed with the
**Calibrator** (sneak + right-click a face) — the ecosystem's config tool from
day one. The core block is the craftable item carrying the AI's progression.
Sliding 64-op diversity window (100% → 10% floor
past 25% share). 5 levels (0/500/1500/3500/6500 XP): N2 Speed, N3 Efficiency,
N4 Yield, N5 critical (capped, "tier 2 coming soon"). 2 module slots per
machine, identical modules stack; gate applies on insertion, crafting stays
open. All knobs in `KoiosBalance` (future config hookup).

## Built

- **`koios/` package (common)**: `KoiosBalance` (all numbers), `KoiosCoreBlock`
  (FORMED blockstate, never ticks — ADR-012), `KoiosCoreBlockEntity` (ring
  buffer + per-key counts, O(1) diversity factor; event-driven multiblock
  revalidation from placement/frame changes/GUI open), `NeuralCasingBlock`
  (pokes cores within 1 block on place/remove), `KoiosNetwork` (v0 static
  per-dimension core index, register in `setLevel`/unregister in `setRemoved`,
  lazy purge; closest formed core within 32 blocks), `KoiosCoreMenu` +
  `KoiosCoreScreen` (display-only: status, level, diversity, unlock list, XP
  bar; XP ships as low/high pair per the shorts convention).
- **XP is never lost**: custom data component `krios_industry:koios_data`
  (first `DataComponentType` through the registrar — generic register works on
  both loaders). Loot table copies it onto the drop (`copy_components`),
  `applyImplicitComponents` restores it on placement keeping
  `max(existing, item)`; `removeComponentsFromTag` avoids NBT duplication.
- **Modules**: `ModuleItem`/`ModuleType` (Speed ×1.5/module, Efficiency
  ×0.8 energy/module, Yield +25%/module). Crusher gained 2 module slots
  (GUI-only, hoppers can't touch them), integer-math effects, and a
  quarter-item yield accumulator (deterministic remainder, no RNG — ADR-006).
  Insertion gated by `KoiosNetwork.coreLevelAt` (server-authoritative slot).
- **Reporting**: crusher reports each craft keyed by recipe id; generator
  reports each burn cycle keyed by fuel item (varied fuels teach more).
- Recipes (casing ×4, core, 3 modules — `c:` tags per ADR-008), loot tables,
  blockstates/models, en+fr lang, tab entries, script-generated placeholder
  textures (blocks, modules, core GUI; crusher GUI patched with 2 slot squares
  at (151,27)/(151,51) — slots at (152,28)/(152,52)).
- **Screen/head layer** (second pass, same day): casings carry a FORMED state
  the core flips for the whole shell (seamless texture = one visual mass);
  `KoiosCoreRenderer` (client BER, registered per loader) draws the head on
  the screen face — eyes tracking the nearest player, blinks, 2.5s boot
  static, learning pulse, level-up flash + smile. Animations ride vanilla
  block events (`EVENT_PULSE/LEVEL_UP/BOOT`); screen side + XP sync via
  `getUpdateTag`/`getUpdatePacket` (first client-synced BE). Formation and
  level-up play sounds server-side. `CalibratorItem` (`tool/` package):
  sneak + right-click a shell face sets the screen side (actionbar feedback);
  designed as the ecosystem-wide config tool.

## Added for play-testing

- **`/koios` admin command** (permission 2, common Brigadier builder in
  `koios/KoiosCommand`, wired per loader via `RegisterCommandsEvent` /
  `CommandRegistrationCallback`): `info` (level/XP/diversity), `xp <n>`
  (raw XP past the diversity window), `level <1-4>` (pin XP to a level
  threshold, lowering allowed to re-test gates). Targets the closest
  formed core within 32 blocks — same `KoiosNetwork` lookup machines use.
  Motivation: leveling through play is too slow while crushing has a
  single recipe (diversity collapses); stays useful for server admins.

## Fixed during play-testing (NeoForge client, user-validated)

- **Face quads z-fighting**: all head layers sat on one depth plane; the
  translucent sort reordered them per frame (dithered "overlapping renders").
  Fixed with per-layer depth planes (~mm steps).
- **Right eye vanishing during learning pulses**: the pulse overlay sat
  *closer* than the eyes, so compositing depended on draw order and the
  distance sort could kill an eye behind it. Overlays now sit between the
  background and the opaque features — correct in any draw order.
- **Full generator never relighting**: once out with a full buffer, adjacent
  drains didn't re-ignite it and the chain stalled. Consumers now call
  `tryResume()` after a successful pull.

## Gotchas

- `fabric/runs/server/eula.txt` had a UTF-8 BOM (written by PowerShell `>`),
  which makes the server read the key as `﻿eula` and refuse the EULA.
  Write run-dir config files ASCII/no-BOM.
- Vanilla keeps `BlockEntity` component plumbing usable from common:
  `collectImplicitComponents`/`applyImplicitComponents`/`removeComponentsFromTag`
  override cleanly, and loot `copy_components` + `BlockItem` placement handle
  the round-trip with zero platform code.

## Network engine (evening session — designed, built, play-validated)

Design session settled the five open questions (recorded in the design
doc "Network" section): symmetric auto-config pairs resolve to nothing +
Calibrator hint; per-face MANUAL config is the complete contract (gates
third parties too) while virgin/auto faces stay vanilla — auto-config is
just routing, renegotiated from scratch on every new non-manual contact,
and face config never survives break/re-place; face-config UX lives in
the machine UI with the Calibrator covering UI-less blocks; one cable
per core tier, the **last** tier ships cable + wireless (both unlimited,
aesthetic endgame choice), tiers ship as complete slices; the engine
lives in Industry under ADR-013 isolation (one-way deps, graph never
persisted, no balance) until a second mod justifies krios_core.

Built and user-validated in play, both loaders, four phases:

1. **Graph + controller + data**: `network/` package (`NetworkNode`,
   `NetworkConductor`, `Network`, `NetworkManager` — per-dimension,
   event-driven bounded flood fill ≤4096 blocks, position cache, lazy
   recompute during chunk load). Core = controller (active while
   FORMED); one core per network — 2+ controllers = fault, machines drop
   their controller and conflicted cores render TV static + red error
   panel with localized wrapped text. XP rides the machine's own network
   (32-block radius and `KoiosNetwork` deleted); `/koios` targets the
   nearest registered active controller.
2. **Pooled energy + faces + vanilla parity**: `Network.requestEnergy`
   over `EnergyPort` members (generator contributes rate-capped, wakes
   its burner); offline machines fall to furnace parity (200-tick ops,
   x2 recipes at 1:1, modules inert) with the contact transfer kept;
   `FaceConfig` per-face bitmask persisted per BE; hopper + FE/TRE
   gating by MANUAL faces only; contact auto-config with hint on
   symmetric pairs. Face-config UI: "F" side panel in both machine
   screens (ContainerData slots 4-9 + clickMenuButton, zero custom
   packets).
3. **Neural conduit** (tier 1 cable): pure conductor, no BE, multipart
   model, connects to any conductor; recipe copper + neurite dust.
4. **Calibrator diagnostic**: plain right-click on any network block
   opens a live position-anchored readout (status/level, counts, energy
   pool, ambiguous-contact hints); UI blocks skip their own UI via
   `SKIP_DEFAULT_BLOCK_INTERACTION` while the Calibrator is held.

Also: `/koios` admin command (info / xp / level, permission 2) shipped
earlier the same evening to unblock module testing.

### Gotchas (hard-won)

- **Never call `setChanged()` from code that can run during chunk load**
  (BE `setLevel` → engine callbacks): `Level.blockEntityChanged` and the
  comparator scan (`updateNeighbourForOutputSignal`) both sync-load
  chunks → circular wait, server frozen at "Preparing start region".
  Two real deadlocks debugged via jstack. And `getChunkNow` is NOT a
  reliable "chunk still loading" probe: it already returns the chunk
  during `runPostLoad`. Engine-driven persistence marking goes through
  `NetworkManager.markUnsaved` (direct `chunk.setUnsaved`).
- `rtk git commit -m` silently fails on messages containing double
  quotes (`error: unexpected argument`); keep messages quote-free.
