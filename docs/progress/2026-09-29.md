## Machine flow (design: items and energy flow freely inside the network)

- New ItemFlow: machine outputs stream into ADJACENT mod machines through
  touching faces (both contracts respected, target wake via setItem);
  hoppers remain the third-party bridge. Runs per work tick + on every
  neighborhood change (neighborChanged on all three machine blocks).
- Automated insertion only takes processable items (recipe check in
  canPlaceItemThroughFace) — no more dust stuffed into a second crusher.
- Energy: producers PUSH. EnergySink + Network.offerEnergy (two priority
  tiers: working machines fully served before idle buffers see surplus;
  fair-share sweep + leftover sweep, allocation-free, ADR-012). The
  network pull was removed (first-ticking machine tanked the whole stock
  → sequential 100% charges), and a round-robin cursor rotates both
  sweeps' start (the leftover otherwise fed the first non-full sink every
  tick — diagnosed from two /koios energy field snapshots). Machines are
  NOT batteries (design call): consumer buffers never flow back; an idle
  machine spends its own buffer on restart.

## Energy diagnostics (the "pool rises under a deficit" saga)

Instantaneous demand misleads on bursty machines; a trend metric read +0
while everything starved. Final model, user-validated:
- EnergyStats (Industry-side; engine stays balance-free): draw, MEASURED
  consumed, starved flag, stored/capacity per machine; EnergyReport sums.
- Calibrator dashboard (redesigned codex-style, 256x180): status, network
  size, ENERGY section with full-width pool gauge, Production + Consumed
  side by side, Demand (amber on overdemand), red "Machines out of power:
  N", reserve alerts, hints.
- KOIOS alert phrase = starved machines exist ("Machines are waiting for
  power"), resynced event-driven on starved-state TRANSITIONS only (the
  core still never ticks).
- /koios energy op command: per-member breakdown (stored, draw, used,
  supply, STARVED) — the tool that cracked both field mysteries.

## Gotchas (hard-won)

- GuiGraphics y grows DOWN: "raised corners" drawn above the mouth read
  as a smile; a frown needs corners BELOW.
- font.drawInBatch against the shared BufferSource ends the current
  translucent batch: any VertexConsumer captured before it writes into a
  closed buffer ("Not building!" crash). Text goes LAST.
- Full-screen translucent overlays must sit just above the background
  plane: anything with z between overlay and viewer survives any sort
  order; the old blink bug (vanishing quads) was the same family —
  per-frame sliver geometry destabilizing the translucent sort.
- The GUI y-flip (scale -y) inverts winding: with a mathematically
  correct right-handed face basis, single-winding quads get CULLED. Draw
  both windings and cull in view space manually.
- Instantaneous demand vs measured consumption vs trend: on bursty
  machines only measured consumption + a starved flag tell the truth.
- Fair-share + greedy-leftover distribution still serializes: with share
  == per-machine consumption, the leftover all lands on the first
  non-full sink every tick. Rotate the start index.
- Vanilla translation format has no %% escape guarantee across contexts;
  literal % in lang values is safer.
- Recipe-book unlocks for 3x3 recipes only appear in the crafting table's
  book, not the inventory 2x2 book (user confusion, not a bug).

## Per-world difficulty config (ADR-015)

- `config/IndustryConfig` (common): `<world>/serverconfig/
  krios_industry-server.properties`, lazy cache keyed on the server
  instance (WeakReference identity — singleplayer world switches reload
  the right file), human decimals in the file, permille ints in logic,
  failure-tolerant IO, file materialized on first use.
- Two multipliers (0.0-10.0): `energy_cost` (crusher recipe energy +
  furnace E/op) and `xp_rate` (base data XP reported to KOIOS). Applied
  ONLY through `KoiosBalance.scaledEnergyCost/scaledOpXp` — the single
  balance hookup promised by the design doc. Bit-identical at the 1.0
  defaults. XP scaling folded into reportOperations (one site covers all
  three machines); permille×permille kept in long.
- In-game editing: `config` subtree on the op command (list/show/set,
  applied live, persisted). Rejected: ModConfigSpec / Cloth Config +
  ModMenu (per-loader split, hard Fabric deps, generic screens vs
  ADR-014). Codex-style config screen = future chantier, no new deps
  (NeoForge native config button + ModMenu soft entrypoint).
- GUI safety: level thresholds stay client constants (curve not
  configurable in v1 — xp_rate covers the need without syncing
  LEVEL_XP); machine screens only show the already-synced

## Command namespace (ADR-016)

- Canonical root = modid: `/krios_industry config`, `/krios_industry
  koios <info|xp|level|energy>` — lore names are not an interface,
  completion finds everything from the mod's name.
- `/koios` kept as the diegetic alias of the KOIOS subtree only (config

  fresh builder per registration — no Brigadier redirects (end-of-input
  quirks). Deferred: shared `/krios <mod>` root once a second mod ships

## Gotchas (hard-won)

- An annex chassis drawing its title without a width floor bleeds over
  the main frame when content is narrower than the title — the
  localized title must drive the panel's minimum width.
- Menu slots can live at negative coordinates outside imageWidth;
  Slot#isActive gates rendering AND clicks client-side only, so a
  client-menu flag hides annex slots without touching server behavior.
- A slot-hosting annex must render its chassis in renderBg (before the
  vanilla slot/item pass) or its background paints over the items; only
  its tooltip goes late.
- The menu/panel geometry contract (MODULE_SLOT_*) compiles fine when
  mismatched — misalignment is only visible in play; keep both sides
  reading the same constants.
- Per-server lazy config cache: compare the MinecraftServer identity
  through a WeakReference or singleplayer world switches serve the
  previous world's values (and the old server graph leaks).
