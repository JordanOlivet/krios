## The energy hunt: three real bugs, then a policy (2dfda64, d453d5d, a978916)

- **Play verdict (user)**: a wall of full, dark generators never relit
  under a 40-vs-32 E/t deficit; a Mk II crusher stopped feeding the
  furnace below until its face config was re-toggled.
- **Bug 1 — the pool was push-only**: `Network.requestEnergy` had no
  caller (the unbounded pull was removed after a hoarding bug, with no
  replacement). Nothing ever drained idle producers, so
  `extractNetworkEnergy -> tryResume` never relit them. First fix:
  deficit-bounded demand pull in crusher/furnace. Same commit: the
  upgrade kit's in-place block swap silently killed ADR-017 wake chains
  (vanilla drops pending scheduled ticks when the block changes) —
  `UpgradeKitItem` now re-enters the chain after the swap.
- **Bug 2 — a formed core silently inactive (lab find)**: when the core
  BE is born inside another block's place/remove cascade (replacing a
  casing, /setblock), the formation `setBlock` nests inside the outer
  `setBlockState`, and vanilla finishes the outer frame by clobbering
  the BE's cached blockstate with its stale pre-formation state. A core
  formed in the world answered `isFormed() == false`: zero controllers,
  whole component invalid, machines offline on contact energy at parity
  pace, no XP, no pool — and unhealable, because revalidation compared
  against the same stale cache and a same-state `setBlock` is a no-op.
  `isFormed()`/`revalidateStructure()` now read the LIVE level state.
  A lab artifact for the user's world, but a real silent-death class.
- **Retest still failed → the problem was POLICY, not mechanism**: the
  deficit pull fed from the first port in an arbitrary member order
  (BFS from the last recompute seed), so one producer soaked the whole
  drain while the rest sat full and dark, and consumers only pulled
  once their own buffers ran dry — hours of scary "deficit" served
  from reserves.
- **The buffer thermostat (user call, now the pool policy in the design
  doc)**: the network's goal state is *every buffer full*.
  - Consumers top up from the pool whenever not full, rate-capped
    (PULL_PER_TICK — no tanking possible).
  - `requestEnergy` drains round-robin (mirror of `offerEnergy`'s
    rotating cursor): every producer touched relights; production
    tracks demand with no explicit demand signal.
  - Generators pause MID-BURN when full — remaining burn time is kept
    and resumes before any new item is consumed: fuel only ever pays
    for banked energy. Relight hysteresis (~100 ticks of room, ~3% of
    the buffer) so LIT never strobes under a steady drain.
  - Solar untouched: produces whenever it can; at night its bank drains
    into the same round-robin — free energy displaces fuel with no
    explicit priority rule.
  - Lab-verified end-to-end: 9 furnaces (36 E/t) against 4 full dark
    generators — all four relight within seconds, production settles at
    exactly the draw, consumer buffers pinned full, surplus generators
    parked full with their paused burn intact (BurnTime persisted,
    item count unchanged).
- **The test harness that made this possible**: the Fabric dev server
  driven over RCON — `tools/rcon.py` (new, pure stdlib), enable-rcon in
  the fabric run dir, scenarios built with /fill + /setblock +
  /data merge, assertions with /execute if block and /data get.
  `/krios_industry koios energy` gained the POOL line
  (stored/capacity, valid, controllers, component size) — the
  one-command diagnostic for "machines run but the network looks dead".

## Gotchas (hard-won)

- Vanilla clobbers a BE's cached blockstate when the BE is created
  inside another block's place/remove cascade and a nested setBlock
  flips a property: the outer frame ends with `be.setBlockState(stale)`.
  Read the LIVE level state for anything correctness-bearing.
- A same-state `level.setBlock` is a silent no-op: it can never refresh
  a stale BE cache (why the dead core was unhealable via revalidation).
- Vanilla keys pending scheduled ticks by block: ANY in-place block
  swap (upgrade kits) kills the wake chain — re-enter it after the swap.
- Any fixed walk order over pool members concentrates the drain on the
  first port; both offerEnergy and requestEnergy need rotating cursors.
- `/data merge block` reloads a BE without `setItem`: no wake runs —
  poke via a neighbor change in scripted scenarios.
- Javadoc dies on dot-directories inside source trees ("illegal package
  name"): excluded `**/.claude/**` in multiloader-common (javadoc +
  sources jar). Tooling state is excluded, never deleted.
