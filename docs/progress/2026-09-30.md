## Energy scale — two passes in one day

User report: 1 coal = 64,000 E = 160 induction smelts (8 in a vanilla
furnace). Burn TIME was already vanilla (1600 ticks = 80 s); the rate
(40 E/t) was the problem.

- **Pass 1 — strict vanilla parity (REJECTED in play)**: 2 E/t, a fuel
  worth exactly its vanilla smelting value (coal = 3,200 E = 8 smelts).
  Elegant identity, starved gameplay: one generator barely fed one
  furnace. "Le nerf est beaucoup trop violent."
- **Pass 2 — machine-park sizing (VALIDATED)**: the user set the spec —
  one generator feeds 4 induction furnaces. Generator = **16 E/t**;
  coal = 25,600 E = 64 smelts = **8× its stone-furnace value** (the
  multiplier IS the tech reward, classic tech-mod range). Unit price
  400 E/smelt; **a crush costs two smelts** (ores 1600→800 E, raw
  1200→600, cobble/gravel 400→200; times unchanged). Buffers: generator
  50,000 E (~2 coals), crusher/furnace 8,000 E. `EnergyBuffer.load`
  clamps, so over-capacity saves self-correct.
- Design doc carries the dated bullet with the rejected option and why;
  a memory note records the method (size on park ratios, not parity
  anchors — one knob moves, the frame holds).

## Gotchas (hard-won)

- A vanilla-parity energy anchor reads elegant and starves play; size
  balance on machine-park ratios and state the resulting pacing.
- A screen-chrome unification silently flattens per-machine agreements
  (the generator's horizontal bar); carry the exceptions explicitly.
- BE update-tag sync: the client drops an EMPTY tag (`onDataPacket`
  skips it) — always ship the Faces array or a full face reset never
  reaches watching clients.
- `sendBlockUpdated` is safe in contexts where `setChanged` is not:
  `blockChanged` only queues on an already present chunk holder.
- Client-side proximity scans: iterate `chunk.getBlockEntities()` over
  the few chunks in range, not `getBlockEntity` over a blockpos cube.

## Gotchas (hard-won)

- **Never round-trip source files through WinPS text cmdlets**: the
  documented BOM gotcha has a second door — `Get-Content -Raw` without
  -Encoding reads UTF-8 as ANSI (em-dashes became mojibake) and
  `Set-Content -Encoding utf8` writes a BOM javac rejects. Repairs via
  Python; rule added to CLAUDE.md.
- PowerShell `[char]+[char]` is integer addition, not concatenation —
  a "pattern" built that way silently matches nothing.
- The `:javadoc` task fails the build on `<->` in a doc comment
  (malformed HTML).
- Slot x/y are final: per-tier slot POSITIONS cannot follow the synced
  tier, only visibility can (isActive). A t1 machine shows its single
  column off-center left — px iteration pending with the user.
- An upgrade-kit block swap must clearContent() the old BE after
  saving its tag, or onRemove's dropContents scatters the inventory.
