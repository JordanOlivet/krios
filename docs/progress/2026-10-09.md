## Quantum Lure — design (user calls)

- **No rod slot** (user, ADR-024): a machine meant to automate must not
  need refilling with a tool. A tool's enchantments become modules on
  the points model: **Lure** (-100 ticks of wait per point) and **Luck**
  (+1 luck per point, uncapped; around 5 points the vanilla junk weight
  hits zero, so Luck is the junk filter). Lure-only, refused elsewhere
  by `mayPlace`; same bay as the process modules (option A — choosing
  is the game). Unlocks: Lure with Speed (N2/N6), Luck with Yield (N4/N8).
- **Fixed 5×5 zone** behind the screen at every tier (user: a resizable
  zone serves no purpose); **tier brings lines** 1/2/4/8. A cell fishes
  with source water at Y-1 under air or a lily pad: 25/25 = open water
  (treasure), fewer = no treasure, none = idle.
- **Per-line vertical gauges** in the terminal (user), computed from game
  time at menu sync, so they move smoothly while the machine only wakes
  per catch. Plus a 5×5 water map (each cell lit when valid) and an
  `n/25` readout.
- Placeholders: 200 E per catch, `LURE_XP_PERMILLE` = 300 (3 XP),
  diversity key `fish:<item>`.

## Implementation notes

- Vanilla table through a real loot context (rod tool, module luck,
  zone center as origin). Treasure is gated by vanilla's open-water
  predicate on THIS_ENTITY: in open water we pass a detached
  `FishingHook` (open by default, never added to the world).
- One scheduled wake for the next due line (ADR-022); no cell scan.
- **Core split (ADR-025)**: `ZoneMachineBlockEntity` (zone fixed or
  tier-driven, wake chain with machine-supplied work/delay/idle state,
  energy, buffer, faces, modules, generic input area) →
  `PlantingZoneBlockEntity` (plant slots, scan, forced growth, routing +
  voiding) → farmer/forester; the Lure extends the core directly. Menus
  and screens split the same way. NBT keys and slot layout unchanged for
  the planting machines.
- Grinder and forge now accept only the process axes
  (`ModuleType.isProcessAxis`).
- KOIOS unlock lines and the Progression ladders name the new modules
  (texts lengthened, the core screen held in play).

## Play-test fixes (user, same session)

- **Outputs only left after an action**: between work wakes, push-only
  wakes drain a non-empty buffer every 10 ticks while items keep leaving,
  then fall back to the work cadence. The full-buffer pause stays a true
  stop (wakes only push until room frees or a kick).
- **Modules applied at the next action**: a module swap wakes the
  machine at once (scheduled tick replaced via `LevelTicks.clearArea`),
  and the Lure rescales casts in flight, keeping each gauge's fraction.

## Consigned (user)

- **Responsiveness vs. the tickless policy**: several papercuts trace
  back to ADR-012/ADR-022, and krios_storage will likely add more.
  Measure tickers vs. scheduled wakes, then settle a smoother model
  (e.g. tick while there is work, sleep only when truly idle). Logged in
  the design doc's open questions. Not now.
