## Found and fixed (tooling, not the mods)

- **Rehearsal's 1.21.1 jar was stale** in its checkout's `output/` (built
  before the screen verbs): the first client suite failed on `key` and
  `cursor`. Rebuilt.
- **`op Dev` over RCON ops the wrong player**: for a name the server has not
  seen, it asks Mojang and ops the real account named Dev. The offline
  client was no operator, and Rehearsal's burst of commands got it kicked
  "for spamming". The tool now writes `ops.json` with the offline UUID; the
  README's manual procedure said `op Dev` and is corrected.
- **Rehearsal paces commands on a server** (pushed to its `main`, 4d8d275):
  vanilla adds 20 per command, drains 1 per tick and kicks a non-operator at
  200, which ten commands in one tick reach. `ChatPacer` keeps a burst of
  six, then one every 24 ticks, on any remote server (operators too: the
  client cannot tell them from a permission mod's grants). Proven both ways
  on production servers: a non-operator sending 40 commands was kicked
  before, stays connected now. Builds on 1.20.1 to 26.3, unit-tested.
- **The Fabric dev server's run dir has `online-mode=true`**: an offline dev
  client cannot join it. `--server local` sets offline mode for its run and
  puts the file back.
- The Fabric dev client took a random name (`Player16`); under `-Prehearsal`
  it is `Dev` now, like NeoForge's, so it can be made an operator.

## client_acceptance.py: production clients and local servers

- `--prod`: the built jars on the pinned loader and viewers, launched by
  portablemc from `build/acceptance/client-prod/` (installed once, outside a
  run's timeout).
- `--server local`: starts the matching server (dev, or production with
  `--prod`), makes the player an operator, runs `screens` and `viewers-jei`,
  stops it, reports its log errors, restores `ops.json` and
  `server.properties`.
- A client that is disconnected or refused fails the run at once (it used to
  wait out the 15 minute timeout).
- README and CLAUDE.md updated.
