## What was tested

A scripted scenario drives a dedicated server over RCON, with no player
(chunks force-loaded, time sprinted). It builds the KOIOS multiblock, a
conduit trunk and 21 machines, feeds them the way a hopper would, runs
3600 ticks and reads the world back. Then the server restarts and the
same base is checked again.

Checked each time: the core and its casings form; `/krios_core koios
info`, `/koios energy` and `/krios_core config` answer; the network lists
its 22 members and is valid; the reactor burns fuel; both grinders and
the forge turn out their products; the core gains data XP; the Chrono
Farmer tills, plants and harvests; the Harvest Pod shears; the Phase
Death Field kills the hostile mobs and spares the sheep next door; a
mooshroom and an armadillo exist (the classes two mixins target); a mined
core drops with its `koios_data`; after a restart the network re-forms by
itself and work resumes; nothing is logged as an error.

| Target | Result |
|---|---|
| NeoForge dev server (21.1.80, JEI 19.21.2.313) | build and restart: all pass |
| Fabric dev server (JEI 19.21.2.313) | build and restart: all pass |
| NeoForge **production jars**, NeoForge 21.1.267, JEI 19.76.1.478, EMI 1.1.24 | 50 of 50, restart 15 of 15 |
| Fabric **production jars**, loader 0.20.1, Fabric API 0.116.18, same viewers | 50 of 50, restart 15 of 15 |
| Core **alone**, production, NeoForge and Fabric | boots, both ores generate, multiblock forms, commands answer |

Also checked:

- **Datapacks**: every server loads exactly the files shipped — 1345
  recipes and 1443 advancements with Industry (vanilla 1290 and 1399,
  core 14 and 9, Industry 41 and 35), 1304 and 1408 with core alone.
- **Dev client on NeoForge 21.1.267** (window minimized, sound off): with
  the latest JEI alone, the world loads and JEI lists
  `krios_industry:grinding`; with the latest JEI and EMI together, both
  EMI plugins load. In that second case JEI does not list the grinding
  category: EMI leaves out the JEI plugin of a mod that has an EMI plugin
  of its own (no duplicates), which is the intended outcome.

The first failures were all in the scenario, not in the mods: the vanilla
RCON server drops a packet that arrives glued to another, a fill that
changes nothing counts nothing, and wild animals of the force-loaded
chunks were counted with the test's own.

## The tools (ADR-030, user call)

`docs/analysis/test-automation.md` is the analysis asked for: the layers of
testing, what each catches, what exists, what Rehearsal lacks, the order
of work.

- **Python 3 through uv** (user call; installed on this machine with
  winget, bare `python` stays 2.7).
- **`tools/check_assets.py`**: the static cross-check, both mods.
- **`tools/acceptance/server_acceptance.py`**: the morning's scenario as
  a tool. It installs, starts, drives and stops the servers itself; six
  targets (dev, production jars, core alone, each on both loaders),
  versions pinned in `versions.toml`. Last full run: all green, 75 checks
  on each full target, 14 on each core target.
- **Rehearsal** (the user's client test mod, its own repository, commit
  left local there): twelve new verbs to drive screens — `use`, `hold`,
  `hotbar`, `screen`, `wait screen`, `close`, `slot`, `cursor`, `click`,
  `scroll`, `key`, `type`. Input enters where the window's callbacks do,
  so JEI and EMI answer keys as to a user. Minecraft 1.20.1 and 1.21.1;
  a failed reply on the later versions.
- **`tools/acceptance/client_acceptance.py`**: a dev client with
  `-Prehearsal` (own game directory, 1280x720 window in the background,
  sound off) runs the command files of `tools/acceptance/client/`:
  `screens` (with JEI, then EMI), `world`, `viewers-jei`, `viewers-emi`.
  NeoForge and Fabric.
- **Visual review**: the agent read the screenshots. They confirm the
  terminals after the core split, the unlock list, the Codex order, the
  viewers keeping off the annex panels, the emissive ores on both loaders
  (a vanilla ore next to them stays dark), the Calibrator's overlay,
  diagnostic screen and blueprint, the core's screen side, the Grinding
  category in JEI and EMI, the information pages.
- **One defect found and fixed**: in EMI the Grinding category wrote
  energy and duration in white shadowed text on a light background ("800
  E" read "899 E"); now dark, without a shadow.

This covers the visual list the user was going to check by hand, except
creative tabs. It does not replace their first look at the game: nobody
has *played* it since the core split.
