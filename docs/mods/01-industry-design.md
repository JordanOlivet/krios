# Krios: Industry — Design

**Status**: core design settled (Q&A sessions 2026-09-20); implementation-time choices settled (Q&A 2026-09-25, see "Settled at implementation").

## Pitch

The industrial heart of the Krios ecosystem. Automate, optimize and accelerate every classic Minecraft process (crafting, smelting, …) to absurd speeds, and extract more from the same resources. All of it orchestrated by K.O.I.O.S., the AI core, and powered by quantum/temporal machinery.

## Progression model

### Dual axis

- **Hardware** — machine **tiers** (4 total) + slotted **upgrade modules**. Tiers set the ceiling; modules fine-tune within a tier. Tier 4 delivers the "quasi-infinite" machines of the pitch.
- **Software** — the KOIOS core's levels. Strict separation of roles: software **unlocks** (modules, tier gates), hardware **performs** (speed, efficiency, yield).

### KOIOS core

- Small functional **multiblock**, present from the MVP. The mod's identity anchor.
- Levels up with **data XP** generated by machine operations on the network — the AI learns by watching your industry run.
- **Diversity bonus**: varied operations teach more; repeating the identical operation has diminishing returns. Anti-AFK-farm, and it pushes players toward a real, varied industry.
- **Classic levels** unlock upgrade modules progressively.
- **Critical levels** (one per tier boundary) unlock the next machine tier and cost **items + XP** — the AI needs a material breakthrough to cross a software ceiling. The two axes meet at every tier gate.

### Alternative path: craftable cores

- Cores of any tier N are **directly craftable**, expensively — the player pays in resources what they skip in time.
- Anti chicken-and-egg rule: a tier N core recipe only ever costs **bulk tier N-1 outputs**, never tier N products.
- A crafted tier N core arrives with all classic levels ≤ N acquired (modules unlocked) and sits at the critical threshold of tier N+1.
- Core replacement/upgrade keeps `max(existing progression, crafted progression)` — XP is never lost.
- **Pack-maker control, zero special code** (per ADR-007): remove the core recipes → forced-learning mode; cheapen them → direct-access mode. A config multiplier scales data XP gain.

## Machines (MVP = full tier 1 slice)

Naming: sober, no prefix (the Krios brand carries the identity; short names stay readable in GUIs/JEI).

| Machine | Role |
|---|---|
| Generator | Burns fuel → energy. Deliberately boring tier 1. |
| Crusher | Ore → dust with an **evolving multiplier**: starts at x2, grows with yield modules (x2 → x2.5 → x3 …). No multi-machine chain — one machine, deeper upgrades, quantum-recomposition lore. |
| Furnace | Energy-powered, faster smelting, module slots. |
| KOIOS Core | Multiblock; data XP, levels, module unlocks, UI. |

## Modules (MVP)

Speed, Efficiency (energy cost), Yield (crusher multiplier). All gated behind KOIOS classic levels, and inert while the machine is not connected to a KOIOS network (see Network).

## Materials

- **Chronite** — time-infused crystal; hardware-axis components.
- **Neurite** — data-conductive mineral; software-axis components.
- Common metals through `c:` tags (copper, tin, steel, titanium, …) — modpack ore sets plug in automatically (ADR-008).

## Worldgen

- MVP: overworld veins for both ores. Nothing else.
- Post-MVP: small ruined **laboratory structures** containing both ores and lore-flavored loot.

## Network (vision, 2026-09-25 — post-MVP)

The KOIOS core is the **controller of the whole factory** (see VISION.md "The
network"): machines must be connected to a core to operate, first through a
single universal cable (energy + items + fluids + data in one conduit), later
wirelessly as the progression advances. One network per core; the network
replaces both v0 stopgaps (crusher adjacency energy pull, 32-block XP radius).

Settled (Q&A 2026-09-25):

- **Bootstrap through vanilla**: both ores smelt 1:1 in a vanilla furnace and
  the tier 1 core recipe only needs furnace-obtainable materials (the current
  recipe already complies) — no mod machine is required before the first core.
- **Vanilla parity when disconnected**: mod machines still run without a
  network, but only as well as their vanilla equivalent (furnace-grade
  speed/efficiency — same baseline as vanilla), and modules are inert.
  Connecting to a KOIOS network unlocks the machine's real performance and
  its upgrades.
- **Network capacity, if any, is a config**: the "KOIOS attention" idea
  (machine count capped per level) risks AE2-channel frustration, so if it
  ships it sits behind a config multiplier up to infinite (AE2-style x2/x4/x8/∞,
  ADR-007 spirit); base capacity TBD.
- **The Calibrator gets a dedicated diagnostic UI** for network inspection,
  not just actionbar feedback.
- **Yield is a network benefit**: disconnected, the crusher works 1:1 at
  furnace-grade speed; connected, x2 and full speed. Recipes without a vanilla
  equivalent (cobble→gravel→sand) stay available disconnected, just slow.
- **Machines are network nodes**: mod blocks propagate the network by
  adjacency, AE2-controller style — a chain of touching mod machines is
  networked as soon as one element reaches a formed core (the casing shell is
  the connection surface). Energy, items, fluids and data all flow through the
  chain; cables only bridge gaps, wireless replaces them later.
- **Disconnected generator**: buffers energy, idles unlit when full, resumes
  when a drain frees room, and feeds any adjacent consumer — mod machine or
  third-party FE/TRE block.
- **Per-face interaction config**: every machine face carries a configurable
  set of allowed interactions (several types per face possible). The storage
  mod adds AE2-like import/export bus blocks to steer item movement.
- **Contact auto-configuration**: a face that was never configured manually
  configures itself on first contact — when a block lands next to it, both
  touching faces are set to the complementary channels that make the pair
  work (generator beside crusher → energy out / energy in). Manual
  configuration is sacred: autoconfig never overrides it.
- **One core per network**: a connected component may hold a single formed
  core (for now). Connecting a second one brings the network *down* —
  machines drop to vanilla parity, and every conflicted core's screen
  switches to old-TV static with a red error panel dead center, so the fault
  is visible in-world at a glance. Fixing the topology recomputes and reboots.

Settled (design session, 2026-09-25):

- **Symmetric auto-config pairs resolve to nothing**: when both touching
  faces could send *and* receive the same type, no auto-config happens —
  both faces stay virgin and the Calibrator hints at the pair to configure
  manually. Explicit beats magic; no surprise loops or backflow.
- **Per-face config gates everything — manual config, that is** (refined
  2026-09-25 evening): a *manually* configured face is its complete
  contract — intra-network flows *and* third-party exposure (vanilla
  hoppers, FE/TRE neighbors). Virgin *and auto-configured* faces keep
  vanilla behavior: auto-config only records the negotiated flow
  direction, it never restricts third parties. One mental model: what the
  player wrote on a face is what anyone gets; what the machines agreed on
  is just routing. Face config (manual included) does **not** survive
  break/re-place — a re-placed machine is factory-new. A new contact
  between two non-manual faces renegotiates them from scratch (a
  different neighbor gets a fresh negotiation).
- **Per-face config UX = the machine UI** (a 6-face view in each machine's
  screen). The Calibrator handles what has no UI of its own or needs
  in-world orientation/interaction: cables, and later wireless modules
  bridging two blocks. (Its dedicated diagnostic UI stays, see above.)
- ~~**Cable tiers follow core tiers**~~ — revised 2026-09-30 (tier
  model session): **cables are pure connectivity, forever** — one Neural
  Conduit, no per-cable transfer rates. Per-link flow accounting would be
  per-tick work proportional to cable length (against ADR-012), and the
  last tier debrides everything anyway. Limits live at the endpoints
  (machine I/O caps from the machine tier; an optional per-network budget
  from the core tier). The last tier still ships the wireless unlock as
  the aesthetic/comfort choice: organic cable runs vs clean wireless.
- **Tiers ship as complete slices** (2026-09-25): everything a tier
  contains (cable, machines, unlocks, recipes) is designed and lands
  together when that tier is implemented — no tier content drip-fed in
  advance.
- **Engine home**: Industry common, self-contained `network/` package under
  ADR-013 isolation (one-way dependency, graph never persisted, no balance
  in the engine); extracted to `krios_core` when a second mod consumes it.
  Batteries ship in Industry; AE2-like item storage stays `krios_storage`.

## Configurability

- Every recipe (machines, cores, modules) = datapack recipe types.
- Config: progression difficulty multipliers (energy costs, data XP rate, yield curve).

## Non-goals (MVP)

- Pipes/cables/logistics networks
- Machine tiers 2-4 (systems must be tier-ready, content ships later)
- Armor, tools
- World generation beyond the two ore veins (laboratory structures are post-MVP)

## Technical constraints

- Batch processing everywhere (ADR-006) — the evolving multiplier and extreme speeds are arithmetic, never per-item loops.
- Multiloader: common-first code; platform code only for energy exposure and registration (ADR-001, ADR-005).
- Recipes/tags data-driven from day one (ADR-007, ADR-008).

## Settled at implementation (Q&A 2026-09-25)

All numbers live in `KoiosBalance` (single hookup point for the future difficulty config).

- **Multiblock shape**: full 3×3×3 shell of Neural Casing (26 blocks) with the KOIOS Core fully encased at the center; the core block *is* the craftable item that carries the AI's progression (tier 1 only in MVP). Natural build flow: 3×3 casing platform, core on its center, ring around it, 3×3 roof.
- **One entity once formed**: the core flips all 26 casings to a seamless "formed" state so the 3×3×3 reads as a single big block, and every interaction targets the whole — right-clicking any casing opens the core UI, the Calibrator works on any face. Formation/unformation play beacon sounds.
- **The AI's head**: the mod's face, rendered fullbright on one shell face (client-only BER on the core). Eyes track the nearest player, random blinks, boot static sequence on formation, a cyan learning pulse when data XP lands, a flash + wide smile on level-up (vanilla block events — no custom packets). Default screen side: toward the builder at formation; sneak + right-click with the **Calibrator** (the ecosystem's general config tool: screen side today, machine rotation/side config/dismantling later) re-aims it.
- **Data XP / diversity**: sliding window of the last 64 operations (ring buffer + counts). Per-op XP = base × factor; factor is 100% while the operation stays ≤25% of the window, then falls linearly to a 10% floor at pure repetition. Crushing ops: base 10 (key = recipe id); generator burn cycles: base 2 (key = fuel item, so varied fuels teach more).
- **Levels (tier 1)**: 5 levels; cumulative XP 0 / 500 / 1500 / 3500 / 6500. N2 unlocks Speed, N3 Efficiency, N4 Yield. N5 is the critical level toward tier 2 (items + XP) — XP caps there and the GUI shows "coming soon" until tier 2 ships.
- **Modules**: 2 slots per machine at tier 1 (crusher only for now — the generator stays deliberately boring), identical modules stack freely. Speed ×1.5 per module (time ×2/(2+n)), Efficiency ×0.8 energy per module, Yield +25% output per module on top of the recipe (x2 → x2.5 → x3), carried as a deterministic quarter-item accumulator (ADR-006, no RNG).
- **Module gating**: crafting stays open (plain datapack recipes, ADR-007); the KOIOS gate applies on *insertion* — a machine only accepts a module when a formed core in range has the required level.
- **v0 "network"**: machines report operations to the closest formed core within 32 blocks (mirrors the crusher's adjacency energy pull); both get replaced by the real network with scheduled wake-ups.
- **Energy scale (settled 2026-09-30, revised same day after play)**: strict vanilla parity (fuel worth = its vanilla smelting value, 2 E/t) starved everything — one generator barely fed one furnace. The scale is sized on the **machine park** instead: one generator = **16 E/t**, i.e. **4 induction furnaces at full speed** (4 E/t each) or ~3 crushers. Burn time stays the vanilla burn time; a coal (1600 ticks) is worth 25,600 E = 64 induction smelts — **8× its stone-furnace value**, and that multiplier *is* the tech reward on top of speed and modules. Unit price: 400 E per induction smelt; **a crush costs two smelts** (ores 800 E, raw 600 E, cobble/gravel 200 E). Buffers: generator 50,000 E (~2 coals of reserve), crusher/furnace 8,000 E.

## Tier model & tier 2 (design session 2026-09-30)

The tier system, settled ahead of the tier 2 slice. One rule founds everything:

- **Effective tier = min(machine tier, core tier)**. Hardware performs, software caps — in both directions: a tier 1 machine on a tier 2 network keeps working exactly as before (upgrade it to benefit), a tier 2 machine on a tier 1 network is capped at tier 1. Scales to tiers 3-4 with no new concept.

### Machines across tiers (Mekanism-style ladder)

- **Per-tier machine variants**; a tier N machine recipe costs the tier N-1 machine + bulk tier N-1 materials (plain datapack recipes — ADR-007). **No craft gating by KOIOS level**: the min() rule is the effective gate (a tier 2 machine crafted early just performs at tier 1), mirroring the module precedent (craft open, gate at use). Recipe-book advancements may still reveal them at the right moment.
- **In-situ upgrade via consumable upgrade kit** (tier N kit, right-click on the machine, consumed): upgrades in place preserving inventory, modules, energy and face config — the only path that preserves face config, since break/re-place is factory-new by design. No Calibrator mode; the kit is the gesture. The Calibrator keeps its roles (read, configure, project).
- **New machine at tier 2: Solar Panel** — passive generator, day only, lower output than the tier 2 fuel generator but a larger buffer. Tickless via scheduled ticks at dawn/dusk (ADR-012).

### Critical breakthrough (the tier-up ritual)

- Prerequisite: **XP at the tier's cap — a threshold, never consumed** ("XP is never lost" holds). Cost: a crafted **compute chip** (bulk tier N-1 outputs only, per the anti chicken-and-egg rule), **consumed** on use.
- Two gestures, same effect: a dedicated slot in the core UI, or right-click the formed structure with the chip. A big in-world animation marks the moment (block-event channel, BER sequence — no custom packets).

### Levels beyond 5 (continuous numbering)

- The breakthrough unlocks the next stretch of the curve. Tier 2: **N6/N7/N8 unlock the Mk II modules** (Speed II, Efficiency II, Yield II; the new energy-production module slots into this ladder — placement decided at the numbers pass), **N9 = critical toward tier 3**. `levelForXp` stays monotonic; the KoiosData component gains the core's tier.

### Energy across tiers

- **A fuel's energy value is constant across tiers** (one coal = 25,600 E, always — the 2026-09-30 energy scale holds). A higher-tier generator produces more E/t by **burning faster**, plus a larger buffer, plus **module slots** (the generator stops being deliberately boring at tier 2).
- **New module type: energy production** (+% energy per fuel) — the only way to extract more from the same fuel.
- All numbers sized on park ratios (machines per generator), per the energy-scale method.

### Yield across tiers

- Base yield rides the machine tier through the quarter-item accumulator (ADR-006, deterministic): **t1 ×2, t2 ×3, t3 ×3 (rest tier), t4 ×4**; yield modules stack on top. Tier 3 breathes so it can shine elsewhere.

### Item transport (tier 2 flagship) and network limits

- **Cables = pure connectivity, forever** (revised from "cable tiers follow core tiers", see Network section): one Neural Conduit, no per-cable rates, no cable zoo. Limits live at the endpoints — machine I/O caps come from the machine tier; if a global ceiling is ever needed it is a **per-network budget from the core tier** (one number, allocation-free). The last tier's wireless unlock remains the aesthetic/comfort choice.
- **The network routes items between machines** at tier 2: both endpoints are nodes with face config; the network moves N items/tick between configured faces as batch arithmetic — items never physically travel through cables (ADR-006/012 by construction).
- **Adjacent inventories only, in Industry**: machine faces exchange with touching containers (chests, third-party mods) through the standard platform item APIs (vanilla Container/WorldlyContainer, NeoForge ItemHandler capability, Fabric Transfer API — same dual-adapter pattern as energy). The insertion discipline (recipe check) applies in both directions. **Pulling from a passive container uses scheduled wake-ups** (~1-2 s, only on machines with a pull-configured face — the first client of the long-promised scheduled wake-ups). Exposing *remote* inventories to the network (import/export buses, "the network sees every chest") is out of Industry's scope: a dedicated block later, or krios_storage's opening move.

### Codex (the guide, renamed from "KOIOS Archives")

- Player-facing rename to **Codex** — a codex is a living compendium (past *and* projected), the internal UI vocabulary already says "codex terminals" (ADR-014), and players know the word. Internal class names migrate opportunistically.
- **Three-band tier visibility, diegetically justified** (Koios, the inquisitive intellect, extrapolates): current tier = *mastered* (first person, normal styling); next tier = **Projections** (distinct styling — dimmed amber, conditional phrasing — with the breakthrough prerequisite shown: the actionable carrot); beyond = corrupted/insufficient-data lines showing only that the ladder has 4 rungs.
- The Projections entry unlocks as XP approaches the cap — KOIOS starts "dreaming" of its next form.
- Presentation: a **"Progression" Codex entry ships with the tier 2 slice**; a graphic tier ladder is absorbed into Codex v3 later; the core's critical notice points to the Codex; existing machine entries carry a one-line contextual projection ("Projection t2: yield ×3" in the crusher entry).
