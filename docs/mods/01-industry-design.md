# Krios: Industry — Design

**Status**: core design settled (Q&A sessions 2026-09-20); implementation-time choices settled (Q&A 2026-09-25, see "Settled at implementation").

## Pitch

The industrial heart of the Krios ecosystem. Automate, optimize and accelerate every classic Minecraft process (crafting, smelting, …) to absurd speeds, and extract more from the same resources. All of it orchestrated by K.O.I.O.S., the AI core, and powered by quantum/temporal machinery.

## Progression model

### Dual axis

- **Hardware** — machine **tiers** (4 total) + slotted **upgrade modules**. Tiers set the ceiling; modules fine-tune within a tier. Tier 4 delivers the "quasi-infinite" machines of the pitch.
- **Software** — the KOIOS core's levels. Strict separation of roles: software **unlocks** (modules, tier gates), hardware **performs** (speed, efficiency, yield).

### KOIOS core

- Small functional **multiblock**, present from the MVP. The mod's identity anchor.
- Levels up with **data XP** generated by machine operations on the network — the AI learns by watching your industry run.
- **Diversity bonus**: varied operations teach more; repeating the identical operation has diminishing returns. Anti-AFK-farm, and it pushes players toward a real, varied industry.
- **Classic levels** unlock upgrade modules progressively.
- **Critical levels** (one per tier boundary) unlock the next machine tier and cost **items + XP** — the AI needs a material breakthrough to cross a software ceiling. The two axes meet at every tier gate.

### Alternative path: craftable cores

- Cores of any tier N are **directly craftable**, expensively — the player pays in resources what they skip in time.
- Anti chicken-and-egg rule: a tier N core recipe only ever costs **bulk tier N-1 outputs**, never tier N products.
- A crafted tier N core arrives with all classic levels ≤ N acquired (modules unlocked) and sits at the critical threshold of tier N+1.
- Core replacement/upgrade keeps `max(existing progression, crafted progression)` — XP is never lost.
- **Pack-maker control, zero special code** (per ADR-007): remove the core recipes → forced-learning mode; cheapen them → direct-access mode. A config multiplier scales data XP gain.

## Modules (MVP)

Speed, Efficiency (energy cost), Yield (crusher multiplier). All gated behind KOIOS classic levels, and inert while the machine is not connected to a KOIOS network (see Network).

## Materials

- **Neurite** — data-conductive mineral; software-axis components.
- Common metals through `c:` tags (copper, tin, steel, titanium, …) — modpack ore sets plug in automatically (ADR-008).

## Network (vision, 2026-09-25 — post-MVP)

The KOIOS core is the **controller of the whole factory** (see VISION.md "The
network"): machines must be connected to a core to operate, first through a
single universal cable (energy + items + fluids + data in one conduit), later
wirelessly as the progression advances. One network per core; the network
replaces both v0 stopgaps (crusher adjacency energy pull, 32-block XP radius).

Settled (Q&A 2026-09-25):

- **Bootstrap through vanilla**: both ores smelt 1:1 in a vanilla furnace and
  the tier 1 core recipe only needs furnace-obtainable materials (the current
  recipe already complies) — no mod machine is required before the first core.
- **Vanilla parity when disconnected**: mod machines still run without a
  network, but only as well as their vanilla equivalent (furnace-grade
  speed/efficiency — same baseline as vanilla), and modules are inert.
  Connecting to a KOIOS network unlocks the machine's real performance and
  its upgrades.
- **Network capacity, if any, is a config**: the "KOIOS attention" idea
  (machine count capped per level) risks AE2-channel frustration, so if it
  ships it sits behind a config multiplier up to infinite (AE2-style x2/x4/x8/∞,
  ADR-007 spirit); base capacity TBD.
- **The Calibrator gets a dedicated diagnostic UI** for network inspection,
  not just actionbar feedback.
- **Energy monitoring overhaul (consigned 2026-10-06, user, not a priority)**:
  the current diagnostic is not reliable enough to act on. In play, every
  reactor was fed and 3 photon arrays were active, yet the panel read a
  deficit (production 360 / consumed 365 / demand 365 E/t) and KOIOS said
  "My energy reserves are running low" with the pool at 42%. Reactors whose
  buffer is full sit idle (thermostat), so a full reactor doing nothing reads
  as lost production. Target: Factorio / Dyson Sphere Program-style
  statistics that let the player see, clearly and reliably, what is
  **produced**, **consumed** and **demanded**, both **right now** and **over
  time** (windowed history/graphs), separating real producible capacity from
  instantaneous output. The low-energy phrase threshold gets revisited in the
  same pass.
- **Yield is a network benefit**: disconnected, the crusher works 1:1 at
  furnace-grade speed; connected, x2 and full speed. Recipes without a vanilla
  equivalent (cobble→gravel→sand) stay available disconnected, just slow.
- **Machines are network nodes**: mod blocks propagate the network by
  adjacency, AE2-controller style — a chain of touching mod machines is
  networked as soon as one element reaches a formed core (the casing shell is
  the connection surface). Energy, items, fluids and data all flow through the
  chain; cables only bridge gaps, wireless replaces them later.
- **Disconnected generator**: buffers energy, idles unlit when full, resumes
  when a drain frees room, and feeds any adjacent consumer — mod machine or
  third-party FE/TRE block.
- **Per-face interaction config**: every machine face carries a configurable
  set of allowed interactions (several types per face possible). The storage
  mod adds AE2-like import/export bus blocks to steer item movement.
- **Contact auto-configuration**: a face that was never configured manually
  configures itself on first contact — when a block lands next to it, both
  touching faces are set to the complementary channels that make the pair
  work (generator beside crusher → energy out / energy in). Manual
  configuration is sacred: autoconfig never overrides it.
- **One core per network**: a connected component may hold a single formed
  core (for now). Connecting a second one brings the network *down* —
  machines drop to vanilla parity, and every conflicted core's screen
  switches to old-TV static with a red error panel dead center, so the fault
  is visible in-world at a glance. Fixing the topology recomputes and reboots.

Settled (design session, 2026-09-25):

- **Symmetric auto-config pairs resolve to nothing**: when both touching
  faces could send *and* receive the same type, no auto-config happens —
  both faces stay virgin and the Calibrator hints at the pair to configure
  manually. Explicit beats magic; no surprise loops or backflow.
- **Per-face config gates everything — manual config, that is** (refined
  2026-09-25 evening): a *manually* configured face is its complete
  contract — intra-network flows *and* third-party exposure (vanilla
  hoppers, FE/TRE neighbors). Virgin *and auto-configured* faces keep
  vanilla behavior: auto-config only records the negotiated flow
  direction, it never restricts third parties. One mental model: what the
  player wrote on a face is what anyone gets; what the machines agreed on
  is just routing. Face config (manual included) does **not** survive
  break/re-place — a re-placed machine is factory-new. A new contact
  between two non-manual faces renegotiates them from scratch (a
  different neighbor gets a fresh negotiation).
- **Per-face config UX = the machine UI** (a 6-face view in each machine's
  screen). The Calibrator handles what has no UI of its own or needs
  in-world orientation/interaction: cables, and later wireless modules
  bridging two blocks. (Its dedicated diagnostic UI stays, see above.)
- ~~**Cable tiers follow core tiers**~~ — revised 2026-09-30 (tier
  model session): **cables are pure connectivity, forever** — one Neural
  Conduit, no per-cable transfer rates. Per-link flow accounting would be
  per-tick work proportional to cable length (against ADR-012), and the
  last tier debrides everything anyway. Limits live at the endpoints
  (machine I/O caps from the machine tier; an optional per-network budget
  from the core tier). The last tier still ships the wireless unlock as
  the aesthetic/comfort choice: organic cable runs vs clean wireless.
- **Tiers ship as complete slices** (2026-09-25): everything a tier
  contains (cable, machines, unlocks, recipes) is designed and lands
  together when that tier is implemented — no tier content drip-fed in
  advance.
- **Engine home**: Industry common, self-contained `network/` package under
  ADR-013 isolation (one-way dependency, graph never persisted, no balance
  in the engine); extracted to `krios_core` when a second mod consumes it.
  Batteries ship in Industry; AE2-like item storage stays `krios_storage`.

## Configurability

- Every recipe (machines, cores, modules) = datapack recipe types.
- Config: progression difficulty multipliers (energy costs, data XP rate, yield curve).

## Non-goals (MVP)

- Pipes/cables/logistics networks
- Machine tiers 2-4 (systems must be tier-ready, content ships later)
- Armor, tools
- World generation beyond the two ore veins (laboratory structures are post-MVP)

## Technical constraints

- Batch processing everywhere (ADR-006) — the evolving multiplier and extreme speeds are arithmetic, never per-item loops.
- Multiloader: common-first code; platform code only for energy exposure and registration (ADR-001, ADR-005).
- Recipes/tags data-driven from day one (ADR-007, ADR-008).

## Settled at implementation (Q&A 2026-09-25)

All numbers live in `KoiosBalance` (single hookup point for the future difficulty config).

- **Multiblock shape**: full 3×3×3 shell of Neural Casing (26 blocks) with the KOIOS Core fully encased at the center; the core block *is* the craftable item that carries the AI's progression (tier 1 only in MVP). Natural build flow: 3×3 casing platform, core on its center, ring around it, 3×3 roof.
- **One entity once formed**: the core flips all 26 casings to a seamless "formed" state so the 3×3×3 reads as a single big block, and every interaction targets the whole — right-clicking any casing opens the core UI, the Calibrator works on any face. Formation/unformation play beacon sounds.
- **The AI's head**: the mod's face, rendered fullbright on one shell face (client-only BER on the core). Eyes track the nearest player, random blinks, boot static sequence on formation, a cyan learning pulse when data XP lands, a flash + wide smile on level-up (vanilla block events — no custom packets). Default screen side: toward the builder at formation; sneak + right-click with the **Calibrator** (the ecosystem's general config tool: screen side today, machine rotation/side config/dismantling later) re-aims it.
- **Data XP / diversity**: sliding window of the last 64 operations (ring buffer + counts). Per-op XP = base × factor; factor is 100% while the operation stays ≤25% of the window, then falls linearly to a 10% floor at pure repetition. Crushing ops: base 10 (key = recipe id); generator burn cycles: base 2 (key = fuel item, so varied fuels teach more).
- **Levels (tier 1)**: 5 levels; cumulative XP 0 / 500 / 1500 / 3500 / 6500. N2 unlocks Speed, N3 Efficiency, N4 Yield. N5 is the critical level toward tier 2 (items + XP) — XP caps there and the GUI shows "coming soon" until tier 2 ships.
- **Modules**: 2 slots per machine at tier 1 (crusher only for now — the generator stays deliberately boring), identical modules stack freely. Speed ×1.5 per module (time ×2/(2+n)), Efficiency ×0.8 energy per module, Yield +25% output per module on top of the recipe (x2 → x2.5 → x3), carried as a deterministic quarter-item accumulator (ADR-006, no RNG).
- **Module gating**: crafting stays open (plain datapack recipes, ADR-007); the KOIOS gate applies on *insertion* — a machine only accepts a module when a formed core in range has the required level.
- **v0 "network"**: machines report operations to the closest formed core within 32 blocks (mirrors the crusher's adjacency energy pull); both get replaced by the real network with scheduled wake-ups.
- **Energy scale (settled 2026-09-30, revised same day after play)**: strict vanilla parity (fuel worth = its vanilla smelting value, 2 E/t) starved everything — one generator barely fed one furnace. The scale is sized on the **machine park** instead: one generator = **16 E/t**, i.e. **4 induction furnaces at full speed** (4 E/t each) or ~3 crushers. Burn time stays the vanilla burn time; a coal (1600 ticks) is worth 25,600 E = 64 induction smelts — **8× its stone-furnace value**, and that multiplier *is* the tech reward on top of speed and modules. Unit price: 400 E per induction smelt; **a crush costs two smelts** (ores 800 E, raw 600 E, cobble/gravel 200 E). Buffers: generator 50,000 E (~2 coals of reserve), crusher/furnace 8,000 E.

## Tier model & tier 2 (design session 2026-09-30)

The tier system, settled ahead of the tier 2 slice. One rule founds everything:

- **Effective tier = min(machine tier, core tier)**. Hardware performs, software caps — in both directions: a tier 1 machine on a tier 2 network keeps working exactly as before (upgrade it to benefit), a tier 2 machine on a tier 1 network is capped at tier 1. Scales to tiers 3-4 with no new concept.

### Machines across tiers (Mekanism-style ladder)

- **Per-tier machine variants**; a tier N machine recipe costs the tier N-1 machine + bulk tier N-1 materials (plain datapack recipes — ADR-007). **No craft gating by KOIOS level**: the min() rule is the effective gate (a tier 2 machine crafted early just performs at tier 1), mirroring the module precedent (craft open, gate at use). Recipe-book advancements may still reveal them at the right moment.
- **In-situ upgrade via consumable upgrade kit** (tier N kit, right-click on the machine, consumed): upgrades in place preserving inventory, modules, energy and face config — the only path that preserves face config, since break/re-place is factory-new by design. No Calibrator mode; the kit is the gesture. The Calibrator keeps its roles (read, configure, project).
- **New machine at tier 2: Solar Panel** — passive generator, day only, lower output than the tier 2 fuel generator but a larger buffer. Tickless via scheduled ticks at dawn/dusk (ADR-012).

### Critical breakthrough (the tier-up ritual)

- Prerequisite: **XP at the tier's cap — a threshold, never consumed** ("XP is never lost" holds). Cost: a crafted **compute chip** (bulk tier N-1 outputs only, per the anti chicken-and-egg rule), **consumed** on use.
- Gesture (revised at implementation, 2026-09-30): **right-click the formed structure with the chip** — any casing face, the structure acts as one block. The originally considered core-UI slot was dropped: the core terminal is display-only (no player inventory), a lone slot there would be unusable without rebuilding a validated screen. The terminal's critical notice carries the actionable prompt instead. A big in-world animation marks the moment (block-event channel, BER sequence — no custom packets).

### Levels beyond 5 (continuous numbering)

- The breakthrough unlocks the next stretch of the curve. Tier 2: **N6/N7/N8 unlock the Mk II modules** (Speed II, Efficiency II, Yield II; the new energy-production module slots into this ladder — placement decided at the numbers pass), **N9 = critical toward tier 3**. `levelForXp` stays monotonic; the KoiosData component gains the core's tier.

### Parallel processing slots (settled 2026-09-30, evening)

- **For processing machines, a tier brings SLOTS, not speed** (Mekanism
  factory reference): **1 / 2 / 4 / 8** parallel process columns at
  t1/t2/t3/t4 — powers of two, per the doubling invariant. Each column
  runs at the baseline pace (2× vanilla + shared modules); speed gains
  beyond that are the modules' job. Energy per operation is unchanged —
  draw scales naturally with active columns, so the macro-economy is
  identical to a speed doubling (a fully loaded Mk II furnace pulls
  8 E/t; the park ratio holds) while reading as visible parallel
  operations (the batch pillar, on screen).
- The min rule gates the ACTIVE columns: a Mk II machine on a tier 1
  core processes on one column; the machine's own tier gates which
  slots exist physically (fillable). Generators are not processors:
  they keep the rate/burn-speed doubling (and the solar panel follows).
- UI: vertical columns (input → progress → output) in the terminals'
  reserved work center, Mekanism-style; px iteration from screenshots.
- Noted for later, not designed: a core-UI slot returns with the
  network item link (AE2 wireless-terminal style); a module-system
  rework (Mekanism-style mixed modules with per-type caps) is on the
  user's mind but not settled — the current system is not fully
  satisfying either.

### Energy across tiers

- **A fuel's energy value is constant across tiers** (one coal = 25,600 E, always — the 2026-09-30 energy scale holds). A higher-tier generator produces more E/t by **burning faster**, plus a larger buffer, plus **module slots** (the generator stops being deliberately boring at tier 2).
- **New module type: energy production** (+% energy per fuel) — the only way to extract more from the same fuel.
- All numbers sized on park ratios (machines per generator), per the energy-scale method.
- **Pool policy: the buffer thermostat (user call 2026-10-02, play-driven)**. The network's goal state is *every buffer full*. Working machines top up from the pool whenever not full (rate-capped pulls, round-robin across producers so no single one soaks the drain); every pull relights the producers it touches, so production tracks demand with no explicit demand signal. A generator whose buffer tops up **pauses mid-burn-cycle** — remaining burn time is kept, the item only ever pays for banked energy, nothing is wasted — and resumes on drain (with a ~3% room hysteresis so LIT never strobes). Solar produces whenever it can; at night its bank drains into the same round-robin, so free energy displaces fuel with no priority rule.

### Yield across tiers

- Base yield rides the machine tier through the quarter-item accumulator (ADR-006, deterministic): **t1 ×2, t2 ×3, t3 ×3 (rest tier), t4 ×4**; yield modules stack on top. Tier 3 breathes so it can shine elsewhere.

### Item transport (tier 2 flagship) and network limits

- **Cables = pure connectivity, forever** (revised from "cable tiers follow core tiers", see Network section): one Neural Conduit, no per-cable rates, no cable zoo. Limits live at the endpoints — machine I/O caps come from the machine tier; if a global ceiling is ever needed it is a **per-network budget from the core tier** (one number, allocation-free). The last tier's wireless unlock remains the aesthetic/comfort choice.
- ~~**The network routes items between machines** at tier 2~~ — **withdrawn from Industry 2026-10-01** after play: the component-wide first pass filled any freshly placed machine from across the factory (a new production line could not even be set up), and every fix iterated toward logistics concepts the design kept fencing off as "krios_storage territory" — the signal that the feature lives in the wrong mod. **Cable-borne item transport is now krios_storage's opening chantier**, with the session's design conclusions as its brief: a second, transport-capable cable alongside the pure-connectivity Neural Conduit (two cable kinds forever — the forbidden axis stays rate tiers, not flow kinds), routing scoped to the shared transport-cable run, MANUAL faces required at both endpoints (the universal backbone makes contact ambiguous — touching a cable for energy must never opt a machine into items), the amber hint marking unconfigured faces against a transport cable, round-robin fairness and the insertion discipline at run scope. Industry keeps exactly its LOCAL item behaviors: the hopper-like adjacency flow between touching machines and the manual-face exchange with touching passive containers (scheduled wake-ups, ADR-017).
- **Adjacent inventories only, in Industry**: machine faces exchange with touching containers (chests, third-party mods) through the standard platform item APIs (vanilla Container/WorldlyContainer, NeoForge ItemHandler capability, Fabric Transfer API — same dual-adapter pattern as energy). The insertion discipline (recipe check) applies in both directions. **Pulling from a passive container uses scheduled wake-ups** (~1-2 s, only on machines with a pull-configured face — the first client of the long-promised scheduled wake-ups). Exposing *remote* inventories to the network (import/export buses, "the network sees every chest") is out of Industry's scope: a dedicated block later, or krios_storage's opening move.
- **Implementation session (2026-10-01, settled with the user)**:
  - *Push trigger*: producer-driven, the exact mirror of energy — a machine routes its output batch the moment (and while) it works; no new tickers.
  - *Target fairness*: rotating-cursor round-robin over the network's item sinks (same shape as `offerEnergy`), no priority tiers; the insertion discipline and the per-machine distribution toggle (fill-first/balance via `chooseColumn`) are the only filters, so network flow and hoppers behave identically.
  - *Face semantics for network flow*: an item crosses into/out of the network through a face that (a) its contract allows and (b) physically touches the network — manual blocking an export face really cuts the export. Virgin faces flow by default inside the network ("items flow freely; explicit config restricts").
  - *I/O caps*: machine-to-machine batches are the produced lot (no artificial cap); the only new number is the **pull batch from passive containers: 8 items/wake × effective-tier speed factor** (8/16/32/64, `KoiosBalance` knob).
  - *Wake-up engine*: vanilla scheduled block ticks (ADR-017), ~30-tick cadence, rescheduled only while a manual item face exists.
  - *Passive-container exchange is manual-only*: pushing into and pulling from chests/third-party blocks requires a MANUAL face config (a chest is not a FlowPorts, auto-config never negotiates it); virgin faces keep pure vanilla exposure (hoppers work, nothing active). Explicit beats magic, and it bounds the polling population.
  - *Precedence*: network targets first (machines keep working), manual-face containers take the overflow; the no-core adjacency flow stays as the offline fallback.
  - *Out of this chantier*: the "vanilla parity when disconnected" switch (machines offline already run at parity speed-wise; the full gating sweep is its own later chantier, touching balance, UX and Codex messaging).
  - *Revised same day after play*: the network routing of this session was **withdrawn** (see the struck flagship bullet above) and the whole cable-borne transport concept handed to krios_storage. What stays in Industry from this chantier: the adjacency flow (restored always-on — the first pass had demoted it to offline-only), the manual-face passive-container exchange, the IItemAccess dual adapter, the scheduled wake-ups (ADR-017) and the pull-batch knob. The ecosystem session ran the same day and is consigned: **ADR-018** (three-mod architecture, krios_core as a content mod, ownership map, tier spine, sequencing) and **ADR-019** (layered difficulty config), detailed in `02-core-design.md`. Industry's tier 2 slice is hereby redefined **without transport**: solar panel, Mk II modules + energy module, Codex rename + Progression entry, then the numbers pass (chip/kit recipes, t2 curve) — all BEFORE the core extraction, which triggers when krios_storage starts. At extraction, KOIOS, the ores, the conduit, the Calibrator and the blueprint system leave this mod for core (namespace change assumed, pre-release).

### Solar panel (tier 2 slice, settled 2026-10-01)

- **Production model (ADR-012/017)**: LIT = producing (day + sees sky + buffer room); only a LIT panel ticks. An unlit panel keeps a slow scheduled-wake chain (~100 ticks) checking "can I produce?" — deliberately NO dawn-time math: scheduled ticks count real ticks, so `/time set`, bed skips and `doDaylightCycle` would strand a computed wake; the slow poll self-heals all of them within ~5 s for ~120 checks per full night per panel.
- **Weather**: rain = half rate at Mk I — never zero, so weather creates no light/extinguish transitions to track. **Higher-tier panels are rain-immune** (settled: the tier perk).
- **Numbers (park-ratio frame)**: 8 E/t clear day, 4 E/t rain, 0 at night — "one panel = two induction furnaces while the sun shines", ~1/4 of a tier 1 generator smoothed. Buffer **100,000 E** (produces less than a generator, stores more — user call: it banks its nights). Single tier for now; **Solar Panel Mk II is roadmapped** (not in this slice): rain-immune, rate ladder decided when it ships.
- **Progression**: the gate is the recipe (tier 2 materials; exact costs in the tier 2 numbers pass). No KOIOS gate at use: placed, it behaves like the generator — network pooling online, contact feeding offline.
- **No KOIOS XP**: sunlight teaches KOIOS nothing (no operations, no AFK XP — diegetic and anti-AFK by construction).
- **Identity**: sober name (Solar Panel / « Panneau solaire »). ~~Distinctive low-slab form~~ — revised same day (user): **full machine block, the photovoltaic deck as its top face** — machines stay near-block-size and a full flank meets the conduit arm cleanly. Placeholder textures via gen_textures, Aseprite pass later.
- ~~**v1 scope**: no GUI and no face config~~ — revised 2026-10-01 (user, first contact): **every block gets a terminal showing its state**, and the panel is a machine of full standing: generator-style terminal (wide energy bar, face hologram, voice line) plus a live production state line (full sun / rain / night / saturated, with the current E/t), and **energy-out face config** (one may refuse to feed a face; auto-config negotiates on contact like the generator; manual contracts gate third-party extraction). **Mk II solar gains boost slots** (generator-style bay) when it ships — the Mk I terminal lays out with that space in mind.

### Modules Mk II, the energy module and the points model (settled 2026-10-01)

- **Points model**: every module contributes POINTS on its axis — Mk I = 1, Mk II = 2 — and every formula takes the axis total (speed: time ×2/(2+pts); efficiency: ×0.8^pts; yield: +25%/pt through the quarter accumulator). Marks mix freely in the same slots, zero special cases; a future last-tier "infinity" module is just an absurd point count (user note).
- **Slots follow the machine tier**: 2 at t1, 4 at t2 (same isActive mechanics as the process columns — positions fixed, visibility by tier). **No per-type caps**: the slot count is the natural cap; the Mekanism-style capped rework stays on the table.
- **Caveat, consigned (user)**: the slot-module paradigm itself only half-pleases — adopted because it is the genre default. A deeper, more Krios-native rethink of "how machines get better" is an OPEN design question for a future session; everything here must stay cheap to migrate.

## Machine roadmap (design session 2026-10-06)

Structure per **ADR-020**: every machine is a line (base at t1, improved each tier, one interface), plus a separate **simulated form** unlocked at t4 beside the line's t4 machine. Network energy only unless stated. Names per **ADR-021** (naming pass, same day): the full EN/FR/id table and the line → simulated-form mapping live there.

**Shared rules**
- Self-sufficient processes (fishing, farms, mob farms) earn **reduced KOIOS XP** — something does happen inside them, unlike the solar panel (zero). One permille constant per machine class in `KoiosBalance`, calibrated during the survival playthrough.
- Zone machines configure their zone through the Calibrator overlay (the blueprint/projection system); zones stop at unloaded chunks — never force-load.
- A blocked output fills an internal buffer, then the machine pauses (extinguishes, tickless) until room frees — the thermostat model applied to items.

**The lines**
- **Chrono Farmer** — plants and harvests crops in a zone in front of it. Improved tiers accelerate growth and raise yield. *Simulated form* (**Dyson Garden**): seed + soil block inside, outsized speed/yield.
- **Cyclic Forester** — fells and replants trees in a zone; network energy only (no log fuel). Same progression; simulated form: **Timeless Forest**.
- **Quantum Lure** — next to water, draws the vanilla fishing loot table. A **rod slot**: the rod's enchantments apply (Lure → speed, Luck of the Sea → loot), it wears durability (Unbreaking/Mending matter). Reduced XP. Same progression; simulated form: **Abyss Aggregator**.
- **Quantum Mining Rig** — mines a configured X/Z area between a Y min and a Y max; mined items exit **from the quarry block itself**. Ships whole without krios_storage (hopper-limited throughput is the player's call). Tier-2 debut candidate (ADR-020). Open at build time: fluid handling, the protected-block list (bedrock, cores, machines), output buffer size. Simulated form: **Entangled Graviton Core**.
- **Breeding Pod / Harvest Pod / Reaper Array** — operate on creatures present in a zone in front of the block (breed; shear/milk/eggs; kill). Same progression and simulated form.
- **Bio Synthesizer (spawner) + Phase Death Field** — two spawner modes: *default* force-spawns every mob the biome allows in a configured zone (light ignored); *imprint* mode spawns only one creature type from its **neural imprint**. The Phase Death Field damages every mob in its zone (upgrades reach one-shot). Player-only drops and XP orbs need a fake player — a new platform service (both loaders ship one), decided when the Phase Death Field is built. Simulated forms: **Genesis Engine** (Breeding Pod, Harvest Pod) and **Oblivion Engine** (Bio Synthesizer, Phase Death Field, Reaper Array).
- **Magma Reactor** — burns lava (the explicit fuel exception, as a generator). Tier-2 debut candidate (nether access). Starts with buckets, no fluid infrastructure required.
- **The Engram** (formerly "neural imprint") — KOIOS's captured data of a creature: the item that justifies "owning a mob's data". Feeds the spawner's imprint mode and the simulated forms of the creature lines — one concept, several machines. How it is obtained: to design.

**Intermediate items** (microchip, actuator, drill head, condensator, supraconductor...) are born with their first consuming machine, never ahead — then substitute into the compute chip and other recipes au fil de l'eau (numbers-pass decision 2026-10-05).

**Kept in mind, not planned**: Recycler (needs a clear role in the loop first), villagers (breeding first, then trading automation — a whole system), auto-brewer, dedicated composter, fluid infrastructure (only if a machine truly needs it), the generators' simulated analog (concept to come).

### Chrono Farmer (design session 2026-10-08)

The first line machine; it lays the shared zone-machine bricks (zone, pacing, output buffer, reduced XP) that the Cyclic Forester, Quantum Lure and creature lines reuse.

- **Function**: harvests mature crops in its zone (vanilla loot through a proper loot context — Fortune-ready), replants empty farmland (seeds come from the harvest first; the seed slots only bootstrap the field — the field sustains itself), tills dirt/grass in the zone. Hydration stays the player's job.
- **t1 crop scope**: blocks in `minecraft:crops` with a max age (wheat, carrots, potatoes, beetroot, and modded `CropBlock`s for free) + nether wart. Melon/pumpkin, sugar cane/cactus, cocoa, berries are deferred — base of the mod first, details later (user call).
- **Tier brings AREA** (the zone analog of process slots): **9×9 / 13×13 / 19×19 / 27×27** at t1→t4 (81 → 169 → 361 → 729, the doubling invariant; 9×9 is exactly what one central water source hydrates). Effective tier = min rule as everywhere.
- **Modules, not tier, bring the rest** (points model): speed = extra random ticks applied to the zone's crops (each costs energy), yield = the quarter-item accumulator, efficiency = energy cost. **No base yield multiplier by tier** — a self-sufficient farm doubling its harvest for free would break the economy.
- **Pacing**: scheduled ticks with idle backoff, never a ticker — **ADR-022**.
- **Inventory**: 3 seed slots (`c:seeds` / `c:crops`), a 9-slot output buffer; buffer full → pause (thermostat model). Output leaves through the faces like every machine (adjacency + manual faces).
- **Energy**: a cost per action (harvest, plant, till) + per accelerated tick; sized on park ratios at the numbers pass.
- **KOIOS XP**: reduced, one permille constant for the farm class in `KoiosBalance`.
- **Zone**: starts in front of the front face, centered on the machine's axis; crops at the machine's Y, soil at Y-1. Size adjustable DOWN (never above the tier max) with -/+ in the terminal. No offset or free shape in v1. Cells in unloaded chunks are skipped.
- **Zone hologram** (user design): shown whenever the Calibrator is held (reuses the blueprint renderer), plus a **"show zone" toggle in the terminal** that pins the hologram without the Calibrator — the Calibrator in hand would hijack right-click (network monitoring), so during setup the player pins it, steps back, closes the terminal and keeps the visual while tuning; unpinned once set up, and grabbing the Calibrator answers "how far does it reach" later. Pins are client-side, per player, not persisted (a setup aid needs no server state).
- **First intermediate: the actuator** (servo — iron, copper, redstone), born in the Chrono Farmer recipe; reused by the Forester, the Mining Rig and later lines.
- **Terminal**: the usual layout — energy bar, seed column, 3×3 buffer, zone-size selector + show-zone toggle, state line (harvesting / waiting for maturity / buffer full / no seeds / empty zone). Mockup before code.
